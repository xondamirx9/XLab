# ТЗ для фронтенд-разработчика

> [!info] Контекст
> Сайты клиентам делают **программисты студии**; сайт студии продаёт их работу.
> Сайт — один файл `site/index.html` на 382 КБ: CSS 74 КБ, JS 258 КБ, данные 8 КБ (107 КБ в gzip).
> В нём сразу публичный сайт, конструктор ТЗ, демо-концепты, встроенная админка и генератор всей страницы.
> Фронт ИИ-студии (страница «Совет агентов», рендерер сайтов от ИИ) удаляется вместе с модулем — FE-12.
> Проблемы — в [[01 Аудит сайта]]. API и шаблоны согласуются с [[ТЗ Backend]], события — по плану из [[ТЗ Data Engineer]], требования безопасности — [[ТЗ Кибербезопасность]].

## Правила

- **Публичный сайт — без фреймворка**: ванильный JS (или TypeScript) модулями, сборка esbuild или Vite. Это лендинг, фреймворк ему не нужен.
- Для админки можно взять лёгкий фреймворк (Preact, Vue), если это ускорит работу. Её код в публичный сайт не попадает.
- **Визуальный язык сохраняем**: токены цветов и шрифтов в `:root`, светлая и тёмная темы, фирменный красный `#B3121B`. Редизайн — не цель.
- Формула цены должна совпадать с ботом. Общие тестовые случаи (`tests/fixtures/estimate_cases.json`: ответы клиента → вилка и срок) проверяются и в Python, и в JS.
- Все тексты — на трёх языках (RU, UZ, EN). Нет перевода — задача не готова.
- Поддержка: последние 2 версии Chrome, Safari (iOS 15+), Firefox, Samsung Internet; ширина от 320 px.

## P0

### FE-01 · Отделить админку от публичного сайта

**Зачем.** Каждый посетитель скачивает редактор, генератор страницы и код публикации. В шапке есть скрытая кнопка «Админка» (`site/index.html:1024`), в подвале — «Вход для владельца».

**Что сделать.**
1. Публичная страница — только сайт и конструктор ТЗ.
2. Админка — отдельное приложение на `/admin` (см. FE-11), свой бандл, вход через сессию ([[ТЗ Backend]] BE-02).
3. Убрать кнопку «Админка» и ссылку «Вход для владельца» с публичного сайта.

**Готово, когда:**
- [ ] В бандле публичного сайта нет кода админки (проверка в CI: поиск по маркерам, размер бандла).
- [ ] JS публичной страницы ≤ 50 КБ gzip.

### FE-02 · Один источник разметки, удалить мёртвый код

**Зачем.** Разметка страницы описана дважды: статически (`site/index.html`, строки 1013–1345) и шаблоном в JS для генератора (строки 2999–3309). Код режима Claude Artifact (`artifactNS`, `window.claude`, `publishOnce`, сохранение файлом) на своём сервере не работает.

**Что сделать.**
1. Страницы рендерит сервер из `site.json` по шаблонам (Jinja2 — договориться с бэкендом, [[ТЗ Backend]] BE-01). Шаблоны и их стили — зона фронта.
2. JS только оживляет готовую разметку: переключатели языка и валюты, конструктор, демо, отправка заявки.
3. Удалить генератор документа (`buildDocument`), встроенный редактор, режимы `export` и artifact.
4. Структура исходников: `frontend/src/` (модули JS/TS, CSS), `frontend/templates/`, сборка в `site/static/` с хешами в именах файлов.
5. Справочники (типы, функции, цены) — из общего `catalog.json` и `site.json`, без копий в JS.

**Готово, когда:**
- [ ] Поменяли текст в `site.json` → он поменялся на всех трёх языковых страницах, без правки JS.
- [ ] В репозитории нет строк `artifactNS`, `window.claude`, `buildDocument`.
- [ ] Конструктор считает так же, как бот: общие тестовые случаи проходят.

### FE-04 · Контакты и быстрые способы связи

**Зачем.** В данных сайта `telegram`, `email`, `phone` пустые; связаться можно только через конструктор.

1. В шапке на широком экране — телефон; в подвале — телефон, Telegram, почта, адрес, часы работы, реквизиты (юрлицо, ИНН), ссылка на бота.
2. Плавающая кнопка «Написать в Telegram» на мобильном (не перекрывает кнопки конструктора).
3. Ссылки `tel:`, `mailto:`, `https://t.me/...` с понятными подписями для экранных дикторов.
4. Админка не даёт опубликовать сайт без хотя бы одного контакта.

### FE-06 · Политика конфиденциальности и согласие

1. Страницы `/privacy`, `/uz/privacy`, `/en/privacy` (текст даёт владелец, требования — [[ТЗ Кибербезопасность]] SEC-09).
2. Ссылка на политику в тексте согласия у формы и в подвале.
3. Чекбокс согласия не отмечен заранее; без него кнопка отправки неактивна и объясняет почему.

### FE-14 · Готовность к строгой CSP

**Зачем.** Сейчас CSP главного сайта разрешает `script-src 'unsafe-inline'` (`app/web.py:65`) — это открывает дорогу XSS. Цель — CSP из [[ТЗ Кибербезопасность]] SEC-02.

1. Ни одного встроенного скрипта и обработчика (`onclick=` и т.п.); весь JS — внешними файлами с того же домена.
2. Данные для JS — `<script type="application/json">` (не исполняется) или `data-*`-атрибуты.
3. Никакого `innerHTML` с данными пользователя: только `textContent` или шаблоны с экранированием. Если `innerHTML` неизбежен — через Trusted Types.
4. Шрифты с собственного домена (FE-08), чтобы убрать `fonts.googleapis.com` из CSP.

**Готово, когда:**
- [ ] Сайт работает с заголовком `Content-Security-Policy: default-src 'self'; script-src 'self'; style-src 'self'; img-src 'self' data:; connect-src 'self'; frame-ancestors 'none'; base-uri 'none'; form-action 'self'` без ошибок в консоли.

### FE-12 · Убрать ИИ-студию из интерфейса

Вместе с [[ТЗ Backend]] BE-13. Сайты делают программисты — в интерфейсах не должно остаться обещаний «сайт от ИИ-агентов».

1. Удалить страницу «Совет агентов» (`app/studio/assets/council.html`) и ассеты рендерера сайтов от ИИ (`site.css`, `runtime.js`) — уходят вместе с `app/studio/`.
2. Проверить сайт, админку и тексты бота на 3 языках: нет «ИИ-агентов», «совета», «сайт за 15 минут».
3. Ссылки на `/council`, `/sites/...`, `/studio/p/...`, если где-то остались, — удалить.

## P1

### FE-03 · Отдельные адреса для языков

1. `/` — русский, `/uz/` — узбекский, `/en/` — английский. Переключатель языка — обычная ссылка на другой адрес (с сохранением якоря).
2. Первый заход на `/`: если язык браузера `uz` или `en` и человек ещё не выбирал язык — показать ненавязчивую подсказку «Есть версия на O‘zbekcha», **без автоматического редиректа** (поисковики должны видеть все версии).
3. Выбор языка запоминается в `localStorage` (как сейчас).
4. `<html lang>`, `hreflang` на все три версии и `x-default`, свой `canonical`.

### FE-05 · Новые разделы

Тексты и материалы даёт владелец; все блоки редактируются в админке (FE-11).

| Раздел | Что внутри |
| --- | --- |
| **Команда** | программисты и дизайнеры: фото, роль, опыт, стек технологий. Сайты делают люди — это главный аргумент, его надо показать |
| **Кейсы** | карточка: задача → что сделали → результат с цифрами, ссылка на живой сайт, скриншот. Шаблон отдельной страницы кейса |
| **Отзывы** | имя, компания, фото (по согласию), текст, ссылка на источник. Не показывать раздел, пока отзывов нет |
| **Поддержка после запуска** | гарантийный срок, что входит (правки, обновления, резервные копии), время реакции, цена — если студия это предлагает. Шаг 5 процесса сейчас заканчивается словом «передаём» |
| **Новости** | 3 последние из `GET /api/news`, ссылка на все |

**Готово, когда:**
- [ ] Пустой раздел (нет кейсов или отзывов) не показывается вообще, а не показывается пустым.

### FE-07 · SEO-разметка

1. `og:image` 1200×630 на каждый язык, `og:locale`, `twitter:card`.
2. Набор иконок: `favicon.ico`, `icon.svg`, `apple-touch-icon.png`, `site.webmanifest`.
3. JSON-LD: `Organization` / `ProfessionalService` с контактами и адресом, `FAQPage` для вопросов, `Offer` для тарифов, `BreadcrumbList` для кейсов.
4. Один `h1` на страницу, логичная иерархия заголовков.

### FE-08 · Шрифты

1. На публичной странице — 2 семейства (Unbounded для заголовков, Onest для текста), с собственного домена, `woff2`, подмножества `cyrillic` + `latin`, `font-display: swap`, `preload` для заголовочного.
2. Шрифты демо-концептов (Literata, Manrope, Oswald, Playfair Display) — грузить только при открытии демо.
3. Подобрать `size-adjust` для запасного системного шрифта, чтобы при подгрузке не прыгал текст (CLS).

### FE-09 · События аналитики

По плану событий из [[ТЗ Data Engineer]] DE-01.

1. Модуль `track(name, props)`: копит события и отправляет пачкой на `POST /api/event` (раз в 5 секунд, при уходе со страницы — `sendBeacon`).
2. `session` — случайный id в `sessionStorage`; **никаких cookie и постоянных id**.
3. UTM и домен реферера — при первом просмотре во вкладке; источник прикладывается к заявке.
4. Ошибка отправки событий никогда не мешает работе сайта.
5. Включение отладки `?debug_events=1`: события печатаются в консоль.

### FE-11 · Новая админка

Отдельное приложение на `/admin`, работает и на телефоне (владелец часто правит с телефона).

| Экран | Что делает | Роли |
| --- | --- | --- |
| Вход | логин и пароль → код 2FA; сообщения об ошибках и блокировке | все |
| Контент | тексты RU / UZ / EN рядом, подсветка непереведённых; цены и сроки; проекты и кейсы; FAQ; контакты | editor+ |
| Медиа | загрузка картинок (перетаскиванием), превью, замена | editor+ |
| Предпросмотр | черновик глазами посетителя на 3 языках, телефон / компьютер | editor+ |
| Публикация | «Опубликовать», история версий: кто, когда, что поменял, откат | owner |
| Заявки | список с фильтрами (статус, тип, канал, дата), карточка: ТЗ, контакты, история, комментарии, смена статуса | manager+ |
| Проекты | проекты в работе: этапы с плановыми и фактическими датами, ответственный, ссылки на прототип и тестовый адрес; просрочки подсвечены. Программист видит только свои ([[ТЗ Backend]] BE-04) | manager+, developer |
| Пользователи | приглашение, роль, отключение, сброс 2FA | owner |
| Журнал | действия пользователей с фильтрами | owner |

Требования:
- Работа только через API бэкенда ([[ТЗ Backend]] BE-01 – BE-04); CSRF-заголовок на изменяющих запросах.
- Черновик не теряется: автосохранение на сервер раз в 10 секунд и предупреждение при закрытии вкладки.
- Проверки перед публикацией: обязательные поля на 3 языках, хотя бы один контакт, корректные цены (нижняя граница ≤ верхней).

### FE-13 · Доступность (WCAG 2.2 AA)

1. Контраст текста ≥ 4,5:1 в обеих темах (проверить `--muted`, текст на `--brand`).
2. Видимый фокус, порядок табуляции, ссылка «К содержанию».
3. Конструктор: подписи у всех полей, ошибки связаны с полем (`aria-describedby`), изменение вилки цены объявляется (`aria-live="polite"`).
4. Диалог демо: ловушка фокуса, закрытие по Esc, возврат фокуса.
5. `prefers-reduced-motion`: без анимаций HUD и параллакса.
6. Поле телефона: `inputmode="tel"`, маска `+998 XX XXX-XX-XX`, но можно ввести и иностранный номер.

### FE-15 · Тесты

1. Playwright e2e: конструктор на 3 языках и в 2 валютах, пропуск шагов, восстановление черновика, отправка (с подменой сервера), ошибки 400 / 429.
2. Визуальные снимки ключевых экранов (первый экран, цены, конструктор, ТЗ готово) — телефон и компьютер, светлая и тёмная темы.
3. Lighthouse CI с бюджетами из таблицы выше; PR, который их нарушает, не проходит.
4. Общие тестовые случаи формулы цены (Python и JS).
